## Acceptance criteria

- `agentskilldraft` schema (required only `skillId`, no conditionals) + optional `Skill.lastAcceptedVersionAt` land via forced re-import; existing objects untouched.
- Drafts are the ONLY self-modification path: active skill content never edited in place; one open draft per skill; provenance + pinned base version recorded.
- Consolidation LLM pass and paired eval gated by kill-switch + budget hard-caps exactly as schedule ticks; spend in the shared budget aggregation.
- Scan covers `learnings.md` as instruction content; dangerous → discard, no override; unavailable scan/eval fail closed (draft stays `proposed`).
- Strictly-worse draft auto-discarded with audit note, learnings retained; no linked evals → `noEvalEvidence`, never grants L5.
- Accept / Edit-then-accept / Reject behind `skill.review-draft` through the Approval state machine (`sourceType: "skill-draft"`, Talk/Notification ping); approving the Approval from ANY surface — generic inbox included — applies the draft via the versioned path; the Approval payload carries deep link + scan verdict + eval delta/`noEvalEvidence` + learnings summary or is invalid; edit-then-accept is SkillDetail-only and re-runs pre-qualification before the Approval is approvable; reject marks learnings excluded from the next proposal.
- Version history = AuditTrail; diff over `frontmatter`/`body`/`files`; rollback-as-new-version; run audit entries pin skill versions (never fatal).
- Post-acceptance regression → advisory rollback suggestion + notification; rollback always explicit.
- Behind-badge + publisher notification + one-click Republish (same publish authorization, own provenance repo only, `learning-candidates.md` stripped); NEVER automatic.
- Every transition/rollback/republish audited; seeded pending draft renders a decidable review surface.
