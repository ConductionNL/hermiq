# ADR-025: Run tokens live in an app table, not in the cache

**Status:** accepted
**Date:** 2026-09-29

Exception ADR under fleet ADR-070 (OpenRegister-backed persistence is the default). Exception class: credential material.

## Context

Every `executionMode: cli` turn and every stage gets a per-run token. The runner hands it to the egress proxy. The proxy presents it to `POST /api/egress/authorize` on every CONNECT, and the CLI presents it to `POST /api/mcp/run`.

The token used to live in `ICacheFactory::createDistributed()`. That cache is shared only when the admin configured `memcache.distributed`. Without it, Nextcloud falls back to `memcache.local`, usually APCu. APCu is per process pool: the web server has one, and every cron run has its own.

So a token minted by a cron-mode background job was invisible to the web server that verifies it. Conversation titles are generated by a background job (`ConversationTitleJob`), and stages can be too.

Measured on the shared dev instance on 2026-09-29, which has no `memcache.distributed`:

- 21:19 a chat turn, minted in the web pool: 13 CONNECTs, all 200.
- 21:20:18 its title job, minted in the cron pool: 11 CONNECTs, all 401 `invalid_token`.
- Each 401 fed the `hermiq_run_token` brute-force counter. From 21:20:37 the proxy's IP got 429 on every call, for every run.
- The next governed run failed with `pdp_rejected` and `pdp_timeout`, and never reached the model.

## Decision

1. Run tokens live in the `hermiq_run_tokens` table, behind `RunTokenStore`. The database is the one store every PHP process of an instance shares.
2. The table holds the SHA-256 digest of the token, never the token. The binding record, the expiry and a consumed flag sit next to it.
3. A consumed or expired record is kept for one hour after expiry. It authorises nothing in that window. It lets `RunTokenService::isKnown()` say the token was genuinely issued.
4. The two token-gated endpoints count a failed token with the brute-force throttler only when the instance never issued it. A spent but genuine token is refused with the same 401 and not counted. A guesser cannot reach that branch: it needs the preimage of a stored digest.
5. Minting sweeps rows whose retention ended, on an indexed column. No background job is needed.

## Why not OpenRegister

A run token lives for minutes and is read on every egress CONNECT. It is credential material, not domain data. It needs no schema, audit trail, RBAC or search, and an object write per turn would cost more than the turn's own dispatch. ADR-070 names credential material as a recognised exception.

## What this re-implements

Nothing that OpenRegister owns. The table has no audit trail, RBAC, search or export, and needs none. Drift is bounded to one table, one store class (`DatabaseRunTokenStore`) and one migration.

## Consequences

**Positive:**
- A token minted anywhere verifies everywhere: web, cron, occ, and every node sharing the database.
- One late component can no longer throttle the egress path for every run behind the same proxy IP.
- The throttle still counts every token the instance never issued.

**Negative / trade-offs:**
- One indexed SELECT per CONNECT, where there used to be a cache read.
- Deploying the change needs the migration to run (`occ migrations:migrate hermiq`, or the next app upgrade).
